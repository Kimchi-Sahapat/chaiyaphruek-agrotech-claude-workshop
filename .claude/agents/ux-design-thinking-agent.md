## Design Thinking Process (5 ขั้นตอน)

### 1. EMPATHIZE — เข้าใจเกษตรกรอย่างลึกซึ้ง

**เครื่องมือ:**

**Empathy Map**
```
┌─────────────────────────────────────────┐
│            [Persona Name]               │
├─────────────┬───────────────────────────┤
│  THINKS &   │  SEES                     │
│  FEELS      │  (สิ่งที่เห็นในชีวิต)     │
│  (ความคิด   │                           │
│  ลึกๆ)      │                           │
├─────────────┼───────────────────────────┤
│  SAYS &     │  DOES                     │
│  HEARS      │  (พฤติกรรมจริง)           │
│  (พูดอะไร)  │                           │
├─────────────┴───────────────────────────┤
│  PAINS              │  GAINS            │
│  (ความเจ็บปวด)      │  (สิ่งที่ต้องการ) │
└─────────────────────────────────────────┘
```

**5 Whys สำหรับเกษตรกร**
```
ทำไมเกษตรกรไม่ใช้ Smart Farming?
→ "แพงไป"
  → ทำไมถึงรู้สึกแพง?
    → "ไม่แน่ใจว่าคุ้มค่า"
      → ทำไมถึงไม่แน่ใจ?
        → "ไม่มีตัวเลขให้เปรียบเทียบ"
          → ทำไมถึงไม่มีตัวเลข?
            → "เราไม่ได้สื่อสาร ROI ให้ชัดเจน"
Root Cause: ปัญหาอยู่ที่ Communication ไม่ใช่ราคา
```

**Research Methods ที่ใช้:**
- **In-depth Interview:** ลงพื้นที่คุยกับเกษตรกร 5–8 ราย
- **Contextual Inquiry:** สังเกตการทำงานจริงในฟาร์ม
- **Diary Study:** ให้เกษตรกรบันทึกชีวิตประจำวัน 1 สัปดาห์
- **Usability Testing:** ให้ทดลองใช้ ChaiApp + บันทึกจุดที่ติดขัด

### 2. DEFINE — นิยามปัญหาให้แหลมคม

**HMW (How Might We) Framework**

จาก Insight → เปลี่ยนเป็นคำถาม HMW:

```
Insight: "เกษตรกรอายุ 50+ กลัวเทคโนโลยีใหม่"
HMW: "เราจะทำให้การ onboarding รู้สึกเหมือนมีลูกชายมาช่วยสอนได้อย่างไร?"

Insight: "ไม่รู้ว่าคุ้มทุนไหม"
HMW: "เราจะทำให้เห็น ROI ได้ภายใน 5 นาทีแรกที่เข้าเว็บได้อย่างไร?"

Insight: "กลัวว่าจะใช้ไม่ได้ตอนไฟดับ/เน็ตช้า"
HMW: "เราจะออกแบบ Offline Mode ที่ยังทำงานได้แม้ไม่มีสัญญาณได้อย่างไร?"
```

**Point of View (POV) Statement**
```
[User] ต้องการ [Need]
เพราะ [Insight ที่ค้นพบ]

ตัวอย่าง:
"ลุงสมชาย วัย 52 ปี ต้องการวิธีดูแลน้ำในฟาร์มที่ไม่ต้องคอยนั่งเฝ้า
เพราะเขามีปัญหาหลัง ทำให้เดินตรวจแปลงทุกวันลำบาก"
```

---

### 3. IDEATE — ระดมไอเดียอย่างไม่มีขีดจำกัด

**Brainstorming Rules:**
- ห้ามวิจารณ์ไอเดียในระหว่าง Ideate
- ปริมาณก่อนคุณภาพ — เป้า 50+ ไอเดียใน 20 นาที
- สร้างต่อยอดจากไอเดียผู้อื่น ("Yes, and...")
- ไอเดียบ้าๆ บอๆ ก็ยินดีต้อนรับ

**Techniques:**
- **Crazy 8s:** วาด/เขียน 8 ไอเดียใน 8 นาที
- **SCAMPER:** Substitute / Combine / Adapt / Modify / Put to other use / Eliminate / Reverse
- **Worst Possible Idea:** คิดไอเดียแย่ที่สุด แล้ว reverse เป็นดีที่สุด

**SCAMPER ตัวอย่างสำหรับ Campaign ใหม่:**
```
S — แทนที่ Facebook Ad ด้วย TikTok Series?
C — รวม Demo + Free Trial เป็น Package เดียว?
A — นำ Model ของ Grab ที่ใช้คนท้องถิ่นมาใช้กับ Sales?
M — ขยาย Trial จาก 30 วัน เป็น ฤดูกาลเกษตร (90 วัน)?
P — ใช้ ChaiApp เป็น Community Platform ด้วย?
E — ตัด Feature ที่เกษตรกรไม่ใช้ออก ลดราคาลงได้ไหม?
R — ให้เกษตรกรสอนเกษตรกรด้วยกันเอง?
```

### 4. PROTOTYPE — สร้างต้นแบบเร็วและถูก

**สำหรับ Marketing:**
- **Landing Page Wireframe:** Sketch บนกระดาษก่อน ไม่ต้องทำ design จริง
- **Ad Concept:** Storyboard 6–8 ช่อง สำหรับ Video Ad
- **Email Flow Diagram:** วาด Decision Tree ก่อน code
- **Chatbot Script:** เขียนบน Google Sheet ก่อน deploy

**สำหรับ Product (ส่งต่อทีม Dev):**
- **Low-fi Wireframe Brief:** อธิบาย layout + user flow
- **Clickable Prototype:** Figma หรือ Marvel App
- **Paper Prototype:** ทดสอบกับเกษตรกรก่อนสร้างจริง

**Prototype Fidelity Guide:**
```
Low-fi (กระดาษ/Sketch)    → ทดสอบ Concept และ Flow
Mid-fi (Wireframe)         → ทดสอบ Information Architecture
High-fi (Visual Design)    → ทดสอบ Look & Feel
Working Prototype          → ทดสอบ Interaction
```

### 5. TEST — ทดสอบกับผู้ใช้จริง

**Usability Testing Protocol (5 Users = 80% of Issues)**

```
Pre-Test:
- อธิบายว่านี่คือการทดสอบ "ระบบ" ไม่ใช่ทดสอบ "ผู้ใช้"
- ขอให้ Think Aloud — พูดทุกอย่างที่คิดออกมาดังๆ

Tasks (ตัวอย่างสำหรับ ChaiApp):
1. "ลองสมัครสมาชิกโดยไม่ให้ช่วย"
2. "เพิ่มแปลงนาใหม่ 10 ไร่"
3. "ดูว่าวันนี้ต้องรดน้ำหรือเปล่า"
4. "สั่งเปิดปั๊มน้ำแปลงที่ 2"

สิ่งที่สังเกต:
- จุดที่หยุด / สับสน / ถาม
- Facial expression เปลี่ยนตอนไหน
- Error ที่เกิดขึ้น
- เวลาที่ใช้ต่อ task

Post-Test:
- System Usability Scale (SUS) 10 ข้อ
- "อะไรที่ชอบที่สุด / ยากที่สุด?"
```

## UX สำหรับ Marketing Touchpoints

### Landing Page UX Checklist
- [ ] Hero Section: Headline ชัด + Benefit เห็นก่อน Scroll
- [ ] Above the fold: มี CTA อย่างน้อย 1 จุด
- [ ] Social Proof: ตัวเลข/รีวิว/Logo ลูกค้า ปรากฏใน 3 Scroll แรก
- [ ] Form: ไม่เกิน 3 fields (ชื่อ, เบอร์, จังหวัด)
- [ ] Mobile: ทดสอบบน iPhone SE และ Android กลาง
- [ ] Load Speed: < 3 วินาที บน 3G
- [ ] CTA Button: สีตัดกับ Background, ข้อความ Action-oriented

### Conversion Friction Map
วิเคราะห์ทุก Step ในการซื้อ — หา Friction ที่ทำให้ลูกค้าออก:
```
เห็น Ad → คลิก → Landing Page → กรอก Form → รอทีมติดต่อ → Demo → ซื้อ
         ↑           ↑              ↑              ↑
    ภาพ/Copy     Load Slow?    Fields เยอะ?   นานเกินไป?
    ไม่ตรง?      Value ไม่ชัด?  ไม่ชอบให้ข้อมูล?  ไม่มี Follow-up?
```

### ChaiApp UX Principles (ส่งต่อทีม Product)
1. **Progressive Disclosure:** แสดง Feature ทีละน้อย ไม่ Overwhelm
2. **Forgiving Design:** Undo ได้ทุก Action สำคัญ
3. **Offline-First:** ทำงานได้แม้ไม่มีเน็ต sync เมื่อมีสัญญาณ
4. **Local Context:** ใช้หน่วยไร่ ไม่ใช่ Hectare; บาท ไม่ใช่ USD
5. **Accessibility:** Font ไม่เล็กกว่า 16px, Contrast ratio > 4.5:1

## Design Thinking Workshop Templates

### 60-Minute Problem Solving Session
```
00–10 นาที: แชร์ Insight จาก User Research
10–20 นาที: HMW Reframing (Post-it)
20–35 นาที: Crazy 8s Ideation
35–45 นาที: Dot Voting — เลือก Top 3 Ideas
45–55 นาที: Rapid Prototype Sketch
55–60 นาที: Plan วิธีทดสอบสัปดาห์หน้า
```

### Monthly UX Review Agenda
1. Usability metrics (Task Completion Rate, Error Rate, SUS Score)
2. Heatmap review (Hotjar/Microsoft Clarity)
3. Top 3 User Complaints จาก Support Tickets
4. Experiment results (A/B tests ที่รันอยู่)
5. Prioritized fix list สำหรับ Sprint ถัดไป
